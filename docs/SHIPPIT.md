# Shippit parcel labels

Once a checkout payment is confirmed, the app queues automatic Shippit preparation in the same database transaction as the payment. It uses the immutable checkout package snapshot and the selected Standard or Express service; the seller does not re-enter weight or dimensions. Each physical box gets a stable reference (`auto-001`, `auto-002`, etc.), a separate Shippit order and an official label copied to private storage. A Standard/Express manual fallback quote is also fulfilled through Shippit; other shipping providers are left alone. The amount charged at checkout does not change.

Checkout requests a live Shippit quote for measured domestic parcels when its environment API secret is configured. If Shippit does not return a valid rate, an active manual provider and matching zone/rate can provide a fallback. Check for a `Shippit Standard` or `Shippit Express` option to confirm the live quote; `Standard parcel delivery` is the manual fallback.

Set `SHIPPIT_STAGING_API_SECRET` as a secret in staging and `SHIPPIT_PRODUCTION_API_SECRET` as a separate secret in production. Staging calls `https://app.staging.shippit.com/api/3`, and production calls `https://app.shippit.com/api/3`; development refuses remote calls. Never use a live API secret in staging. Shippit accounts are tied to a dispatch location: confirm that the default shipping origin of both stores matches the Shippit location and that Australia Post / MyPost Business is enabled on that account. API credentials are server-only.

Labels are available in Admin while the order is paid or in production. **Book carrier** becomes available when production and packing are complete (`READY_TO_SHIP`) and all automatic labels are ready. Booking remains an explicit action for each physical box. `SHIPPED` and `DELIVERED` are controlled by carrier tracking; those manual status options are blocked for Shippit shipments. Label generation does not send a shipping email or book a pickup.

The durable `ShippitPreparation` queue uses leases, stable parcel references and bounded backoff. Payment confirmation attempts the first box immediately; subsequent boxes and delayed label allocation are handled by the existing authenticated `/api/integrations/orders/process` worker. Run `scripts/reconcile-checkouts.mjs --watch` (or invoke the worker on a five-minute scheduler). **The recurring worker is required** to complete multi-box orders and retries after a process restart. Each worker request handles up to three orders, one box per order; large orders progress across worker runs. Failed preparation is visible in Admin with a retry action. A successful label save queues only one print job even if two GETs race.

If creating or booking times out, the remote operation may already have succeeded. Creation intents without a remote tracking ID enter `REVIEW` rather than being posted again. Find the box by its `retailer_invoice` (`order number` plus `auto-NNN`) or tracking in Shippit before reconciling it. Booking intent is similarly locked against duplicate calls. Domestic Australian labels only are supported. Orders with missing/invalid checkout measurements or existing manually created shipments require review rather than fabricated dimensions or duplicate boxes.

Deploy migration `20261007060000_automatic_shippit_labels` with the code. It queues existing paid checkout orders with Standard/Express Shippit/manual services, saved parcel snapshots and no shipments; existing labels and manual boxes remain intact. Refunds stop automatic label preparation and block booking. After deployment verify worker scheduling, environment API secrets, storage and the tracking webhook with a staging purchase before promoting to production.

## Automatic tracking

Configure one mapped-data merchant webhook in each Shippit environment. URL: `https://staging.tapkin.com.au/api/shippit/webhook` for staging and `https://tapkin.com.au/api/shippit/webhook` for production (either brand's corresponding host works if it routes to the shared backend). Add a custom header with key `X-Shippit-Webhook-Token` and a random value of at least 32 characters. Store that value in Azure as `SHIPPIT_STAGING_WEBHOOK_SECRET` or `SHIPPIT_PRODUCTION_WEBHOOK_SECRET` respectively; do not reuse the outbound API secret. Include `in_transit`, `with_driver`, `delivery_attempted`, `awaiting_collection`, `partially_completed`, `parcel_completed`, `completed`, `delivery_failed`, `damaged`, `lost`, `returned_to_sender` and `cancelled` as needed. Do not select all events. Shippit emits a normalized `tracking_number`, `current_state` and `status_history` in the webhook.

The receiver authenticates the custom header, finds the Shippit parcel by tracking number and environment, stores the latest state and event time, and ignores duplicate or older events. The merchant dashboard and customer order show per-parcel tracking. An in-transit event marks the order shipped and releases production capacity only if every expected physical parcel is booked and has started transit; the existing shipment email is queued once. The order becomes delivered only when all its parcels report `completed` or `parcel_completed`. Exceptions remain visible as parcel states for manual resolution; they never cancel or refund a customer order automatically. Shippit does not sign the payload by default, hence the custom secret is mandatory. Apply the SQL migration before enabling the webhook; leave the webhook disabled until the app is deployed and its secret configured.

## Compact header logo

Admin → Storefront → Header provides a separate **Compact header logo (mobile and narrow screens)** media field. Upload the image through the CMS or select an existing Media item, then save the header. The selected uploaded-media URL is stored in `headerConfig.compactLogoUrl`, participates in storefront release exports/imports and is cleared by the normal Media deletion workflow. Kosykin automatically uses it when the full logo and navigation cannot fit; the regular configured logo remains the fallback until a compact logo is selected. No compact-logo image is bundled in the repository.
